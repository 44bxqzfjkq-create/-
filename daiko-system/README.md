# ツムツム代行システム（LINEボット版）手順書

## 全体の流れ

```
お客さん  LINEの「注文」→ フォーム送信 → 「LINEで受付を完了する」ボタンを押して送信
   ↓
管理者    Discordに通知 → 管理ページで「代行中」にする
   ↓
代行者    代行者ページで内容を見て代行 → 「納品完了」ボタン
            （メアド・パスワードが違ったら「ログインできない」ボタン
             → お客さんのLINEに入力し直し用リンクが届く → 入力されたら代行者ページに戻る）
   ↓ （お客さんのLINEに自動で「納品しました」）
お客さん  「ありがとう」「OK」と返信 → 自動で「完了」（Discordの通知も消える）
```

ステータスは **未対応 → 代行中 → 納品済 → 完了** の4つが基本です。ログインできなかったときだけ、**再入力待ち** が入ります。

LINEボットは、その間のお客さんからの質問に自動で答えます。

| お客さんが送ったもの | ボットの動き |
|---|---|
| 1〜9、メニュー、ギフト、質問、納期、料金、流れ、実績 | `FixedReplies.gs` の文章をそのまま返す（AIは使わない） |
| 「進捗」 | 今のステータスを返す（AIは使わない） |
| 「受付番号 T-… コード ○○」 | そのお客さんのLINEと注文を結びつける（受付完了） |
| IDやパスワードらしき文字 | AIに送らない・記録しない。「フォームから送ってください」と返す |
| 納品済のあとの「ありがとう」など | 自動で完了にする |
| 納品済のまま24時間、返事がない | 自動で完了にする（担当者が対応中のお客さんは除く） |
| 納品前の「ありがとう」「了解」など | 「こちらこそ…」と定型で返す（AIは使わない） |
| それ以外の質問 | AI（Claude）が `Manual.gs` の内容だけで答える |
| マニュアルにないこと・返金・クレーム | 「担当者から連絡します」＋Discordに通知。**その後、あなたが「対応済」にするまで、そのお客さんにはAIで返事をしません**（届いたメッセージは毎回Discordに転送） |
| AIを使いすぎたとき（1人1時間30回／全体6時間300回） | 「混み合っています」と返して止める（いたずら・料金の暴走を防ぐ） |

## あなたがやること（この順番で）

### 手順1：秘密の文字を安全な場所に保存する

コードには書かず、Apps Scriptの専用の入れ物に保存します。

1. Apps Script画面の左メニュー「プロジェクトの設定（⚙️）」を開く
2. 下にスクロールして「スクリプト プロパティ」→「スクリプト プロパティを追加」
3. 下の表の「名前」と「値」を、1つずつ追加する（名前は一字一句そのまま）
4. 最後に「スクリプト プロパティを保存」

| 名前 | 値に入れるもの | 必須 |
|---|---|---|
| `LINE_TOKEN` | LINE Developers →「Messaging API設定」→「チャネルアクセストークン（長期）」の文字 | ○ |
| `CLAUDE_API_KEY` | Anthropic Console →「API Keys」で作ったキー | ○ |
| `WEBHOOK_KEY` | **あなたが決める合言葉**。英数字20文字以上（例：`k8Tz2mQ9xW4vB7nR5pL3`）。人に教えない | ○ |
| `ADMIN_KEY` | 管理ページのパスワード（自分で決める） | ○ |
| `WORKER_KEY` | 代行者ページのパスワード（管理者とは別のものにする） | ○ |
| `DISCORD_NORMAL` | 通常チャンネルのWebhook URL | ○ |
| `DISCORD_PRIORITY` | 優先チャンネルのWebhook URL | ○ |
| `LINE_BASIC_ID` | 公式LINEのID（`@`から始まる文字。LINE Official Account Managerの画面に出ています） | ○ |

- 「チャネルシークレット」は使いません。Apps Scriptの仕組み上、LINEの署名確認ができないためです。代わりに `WEBHOOK_KEY`（合言葉）をURLに入れて、合言葉が合わない通知は無視します。
- これまでチャットに貼ったDiscordのWebhook URLは、念のため作り直して、新しいURLを `DISCORD_NORMAL` / `DISCORD_PRIORITY` に入れるのがおすすめです。
- Claude APIは使った分だけ料金がかかります。Anthropic Consoleで月の上限額を決めておくと安心です。

### 手順2：ファイルを貼る

上の「ファイル一覧」のとおりに貼ります。貼ったら保存（Ctrl+S）します。

### 手順3：初期設定を実行する

関数の選択欄で、次の順に選んで ▶実行します（許可の画面が出たら許可）。

1. `setup` … シートの準備と自動のお知らせの設定
2. `checkSecrets` … ログに「必須の設定はすべてそろっています」と出ればOK。「未設定」と出た名前は、手順1に戻って追加
3. `authorizeDrive` … すでに実行済みなら不要

### 手順4：デプロイして、URLを控える

1. 右上「デプロイ」→「デプロイを管理」→ ✏️ → バージョンを「**新バージョン**」にして「デプロイ」
2. 表示される `…/exec` で終わるURLをコピーして、メモしておく（URLは変わりません）
3. そのURLを、スクリプト プロパティに `APP_URL` という名前で追加する（お客さんに送るリンクが、確実にこのURLになります）

### 手順5：LINEとつなぐ

**LINE Developers**（https://developers.line.biz/）
1. 公式アカウントの「Messaging API設定」を開く
2. 「Webhook URL」に、次の形で入れて「更新」
   `手順4のURL?key=手順1のWEBHOOK_KEYの値`
   例：`https://script.google.com/macros/s/xxxx/exec?key=k8Tz2mQ9xW4vB7nR5pL3`
3. 「Webhookの利用」をオンにする
4. 「検証」ボタンは、Apps Scriptの仕組み上あてになりません（合言葉が違っても「成功」と出たり、正しくても「エラー」と出たりします）。本当に動くかは、下の「テスト2」で確かめてください

**LINE Official Account Manager**（https://manager.line.biz/）
1. 設定 → 応答設定
2. 「応答メッセージ」を**オフ**にする（古い自動返信とボットの返事がダブるのを防ぐため）
3. 「あいさつメッセージ」（友だち追加のときの文章）は、そのまま**オン**でOK（ボットは友だち追加には反応しません）
4. 「Webhook」がオンになっていることを確認
5. 「チャット」は、ボットが「担当者から連絡します」と返したお客さんに、あなたが手で返信するために、オンのままがおすすめ（管理ページからも送れます）

**リッチメニューのボタン**

| ボタン | アクション |
|---|---|
| 注文する | リンク → フォームのURL（`…/exec`） |
| 料金表 | テキスト → `料金` |
| 注文の流れ | テキスト → `流れ` |
| よくある質問 | テキスト → `質問` |
| 実績・口コミ | テキスト → `実績` |

### 手順6：中身を入れる

- `Manual.gs` … 【未設定】の項目（納期・返金・BAN保証・優先権・よくある質問）を書く。書いていない項目は、AIが勝手に答えず担当者に回します
  - 上のほうにある `SHOP_NAME`（お店の名前）と `AI_STYLE`（AIの話し方）も、自由に書き換えられます。事実（料金・ルールなど）は `MANUAL_TEXT` のほうに書きます
- `FixedReplies.gs` … プロラインで使っていた返事を貼る。【未設定】のままの番号は、お客さんには送られません

## テスト（本番のお客さんに影響しない順）

### テスト1：ボットの返事だけ確認する（LINEには送りません）

1. 関数の選択欄で `testBotSamples` を選んで ▶実行
2. 下の「実行ログ」に、「お客さん＞…」「ボット＞…」が並びます
3. 見るところ
   - 「料金」「流れ」：決まった返事が出る
   - 「1」：`FixedReplies.gs` に文章を入れる前はAIが答えます（入れたあとは、その文章が出る）
   - 「パスワードは…」の行：ボットが「IDやパスワードはLINEに送らないでください」と返し、お客さんの文は `[IDやパスワードらしき内容のため、破棄しました]` と出る
   - 「進捗」：注文と結びついていないので「まだ注文とLINEが結びついていません」
   - 「ありがとう」：「こちらこそ…」（AIは使わない）
   - 「納期は…」：Manual.gs の納期を書く前は、担当者に回ります
   - 「返金してほしいです」：「担当者から連絡します」と返り、Discordに【テスト】の通知が届く
   - 最後の「いつ連絡もらえますか」：返金の件で「担当者待ち」になっているので、「担当者が確認中です」と返り、Discordに転送される（これが正しい動きです）
4. 終わったら `cleanupTestData` を実行（テストでできた行を消す）

※ AIを使う質問は、実際にClaudeを呼ぶので、ごく少額の料金がかかります。

### テスト2：自分のLINEだけで試す

1. スクリプト プロパティに `TEST_MODE` = `on` を追加（この間、あなた以外のメッセージにはボットは返事をしません）
2. 公式LINEに、自分のLINEから `ID確認` と送る → `U` から始まる文字が返ってくる
3. それを `TEST_USER_ID` として、スクリプト プロパティに追加
4. 自分のLINEから「料金」「1」「納期は？」などを送って、返事を確認

### テスト3：注文から完了まで通しで試す（自分のLINEで）

1. フォームから、テストの注文を送る
2. 完了画面の「LINEで受付を完了する」を押す → LINEが開く → そのまま送信
   - 開かないときは、画面の文章をコピーして公式LINEに送る
3. ボットが「受付番号 … を確認しました」と返せばOK
4. 「進捗」と送る → 「受付済みです」
5. 管理ページ（`…/exec?page=admin`）で、その注文を「代行中にする」
6. 代行者ページ（`…/exec?page=worker`）に注文が出たら、まず「ログインできない」を押す
   → LINEに入力し直し用のリンクが届く → 開いて入力し直す → 代行者ページに「🔁 お客さんが入力し直しました」付きで戻ってくる
7. 「納品完了」を押す
8. LINEに「納品しました」が届く
9. 「ありがとう」と送る → 「確認できました…完了です」と返り、管理ページが「完了」になり、Discordの通知が消える
10. テストの注文行は、シートから削除する

### 本番に切り替える

1. スクリプト プロパティの `TEST_MODE` を**削除**（または `off` にする）
2. リッチメニューを公開

## 毎日の使い方

**管理者**
- Discordの通知（タイトルを押すと管理ページが開く）を見る
- 管理ページで「代行中にする」を押して、代行者に渡す
- 「LINE未連携」と出ている注文は、お客さんがまだLINEに受付番号を送っていません。管理ページの「LINEで送る」は連携後に使えます
- ボットが「担当者から連絡します」と返したお客さんは、Discordに通知が来て、管理ページの上に「🙋 担当者待ちのお問い合わせ」として出ます
  - そこから、お客さんにLINEで返事を送れます（公式LINEのチャットから送ってもOK）
  - その間、ボットはそのお客さんにAIで返事をしません（「担当者が確認中です」と返し、届いた文章をDiscordに転送します）。「料金」「進捗」などの決まった返事は動きます
  - 対応が終わったら「対応済にする」を押してください。ボットの返事が再開します。**押し忘れると、そのお客さんにはずっとボットが答えないので注意**

**代行者**
- 代行者ページを開く → 代行中の依頼だけが出ます（見えるのは、内容・代行するアカウント・備考だけ）
- 終わったら「納品完了」
- メールアドレスやパスワードが違ってログインできないときは「ログインできない」
  - お客さんのLINEに、入力し直し用のリンクが自動で届きます（あなたが間に入る必要はありません）
  - お客さんが入力し直すと、その依頼が「🔁 お客さんが入力し直しました」付きで一覧に戻ってきます
  - お客さんがLINE未連携のときだけ、Discordにリンクが届くので、それをお客さんに送ってください（管理ページの詳細にも出ます）

## 困ったとき

| 状況 | 確認すること |
|---|---|
| LINEのWebhook「検証」が失敗する | 「検証」はあてにならないので、テスト2で確かめる。それでも返事がなければ、URLの末尾 `?key=` の後ろが `WEBHOOK_KEY` と同じか。デプロイを「新バージョン」にしたか。アクセスできるユーザーが「全員」か |
| ボットが返事をしない | `TEST_MODE` が `on` のままになっていないか。LINE Developersで「Webhookの利用」がオンか。特定のお客さんだけなら、管理ページの「担当者待ち」に残っていないか（対応済にすると再開） |
| 「混み合っています」と返ってくる | AIの回数の上限に達しています（いたずら対策）。本当に問い合わせが多いときは `Bot.gs` の `AI_LIMIT_USER` `AI_LIMIT_ALL` を増やして、新バージョンでデプロイ |
| 返事が2回来る | LINE Official Account Managerの「応答メッセージ」がオフか |
| 「担当者から連絡します」ばかりになる | `CLAUDE_API_KEY` が正しいか。実行ログ（左メニュー「実行数」）にエラーが出ていないか。Manual.gsが【未設定】だらけでないか |
| 納品のお知らせが届かない | 管理ページの「LINE連携」が「済み」か。未連携ならDiscordに警告が出ています |
| 入力し直し用のリンクを開くと「リンクが正しくありません」 | スクリプト プロパティの `APP_URL` が、手順4の `…/exec` のURLと同じか |
| 設定を変えたのに反映されない | コードを変えたときは、毎回「新バージョン」でデプロイする（スクリプト プロパティの変更は、デプロイし直さなくても反映されます） |

## まだ確認できていないこと（本物のLINE・Googleでの最初のテストで確認してください）

このフォルダのテスト（`node daiko-system/test/run.js`）は、Google・LINE・Claude・Discordの代わりに仮の部品を使って、54項目の動きを確認したものです。ボットが送る文章が、スマホの吹き出しで変なところで折り返さない長さ（1行＝全角14文字ぶんまで）になっていることも、テストで確かめています。本物のサービスにはつないでいません。

- 「LINEで受付を完了する」ボタンのリンクの形（`https://line.me/R/oaMessage/@ID/?文章`）は、LINE公式の資料を確認できないまま、私の知識で作っています。開かないときは、画面の文章をコピーして送る方法を使えます。そのときは教えてください
- Apps Scriptは、LINEの署名（本物のLINEからの通知かどうかの確認）ができません。代わりに、URLの合言葉で守っています。合言葉が人に知られると、偽の通知を送られる可能性があります
- ボットが読む会話の記憶は、直近10往復・6時間で自動的に消えます。長く続けて話すお客さんには、シートの「依頼内容(要約)」が引き継がれます
- AIの返事はJSONという形式を指定していますが、たまに形が崩れることがあります。その場合は、お客さんに文章を送らず、担当者に回します
