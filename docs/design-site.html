Design Document

株式分析システム 設計書

「業績が良い企業」を並べるのではなく、業績・成長性・バリュエーション・市場期待・株価・リスクを総合的に分析し、さらに過去データで手法そのものを検証できるシステム。投資判断は自動化せず、人間が判断できる状態まで材料を整えることを目的とします。

対象市場 日本株（東証）中心 データ予算 無料基盤＋有料API併用可 出力 Markdown / HTML / CSV ステータス ドラフト（承認待ち） 作成日 2026-08-09
00

設計原則

システム全体を貫く6つの前提

1判断は自動化しない

スコアやランキングは「注目度」であって「買い推奨」ではない。材料整理までを自動化し、最終判断は人間が行う。

2総合＋過去検証

「業績が良い」で終わらせない。6つの観点を総合し、さらに手法自体を過去データで検証できることを最優先要件とする。

3出典を必ず記録

すべてのデータに「出典／取得日時／対象期間／取得パラメータ／APIバージョン」を付与する（Provenance ファースト）。

4Point-in-Time遵守

検証では「その時点で実際に入手可能だった情報」だけを使う。先読み・生存者バイアスを排除する。

5再現性

同じ入力・同じルール設定・同じ基準日なら、同じレポートが再生成できる。設定はすべてファイル化する。

6既存方針の保存

既存の11分析方針を、分析エンジンの11モジュールとして1対1で実装し、方針を壊さない。

システム全体像

6層のパイプライン構成

「候補を絞る → 多面的に分析 → 手法を過去検証 → 監視追跡 → 人間が読めるレポートに集約」という一連の流れをレイヤーで構成します。

02

分析エンジン｜既存11方針のモジュール化

既存方針を 1対1 でモジュールに対応

各モジュールは「入力データ → 指標 → 根拠つき所見 → サブスコア」を返します。総合スコアは重み付き合成で、重みは設定ファイルで外部化します。

#既存方針モジュール主な指標・出力
1企業の業績分析performance売上/営業利益/当期利益の水準・推移、利益率、セグメント別
2決算分析earnings直近実績、会社計画比、進捗率、上方/下方修正、サプライズ
3財務分析financials自己資本比率、ROE/ROA/ROIC、有利子負債、CF、Altman Z 等
4バリュエーション分析valuationPER/PBR/PSR/EV·EBITDA/配当利回り、簡易DCF、過去レンジ内位置
5成長性分析growth売上/利益CAGR、成長の質（一過性か）、再投資効率
6株価分析price_actionトレンド、移動平均、ボラ、相対力（対TOPIX/業種）、出来高
7市場期待との比較market_expectationコンセンサス vs 実績/会社計画、期待の織り込み度合い
8投資仮説の作成hypothesis「なぜ上がりうるか」をドライバー/前提/検証条件で構造化
9反証分析counter_analysis仮説を崩す条件、ベア視点、確証バイアス点検
10リスク分析risk業績/財務/流動性/集中/規制/為替/イベント、下方シナリオ
11複数投資家視点investor_viewsバリュー/グロース/配当/クオンツ 等、視点別評価
「良い企業リスト」との決定的な差 8（仮説）・9（反証）・11（複数視点）は数値だけでなく構造化された文章所見を出します。総合スコアには「反証が強い＝減点」「リスクが高い＝減点」のペナルティ機構を入れ、データ欠損時は0点扱いせず「判定保留」を明示します。

データ取得方法

日本株の主要データソース

ソース取得内容費用位置づけ
J-Quants API
JPX公式		株価、財務諸表、決算発表予定、銘柄マスタ（廃止含む）、投資部門別、空売り、指数無料枠あり／有料で期間拡張中核
EDINET API
金融庁		有価証券報告書・四半期報告書（詳細財務・注記・セグメント／XBRL）無料一次情報
TDnet
適時開示		決算短信、会社計画、修正無料（APIは限定的）補完
yfinance 等
非公式		株価・簡易財務（XXXX.T）無料クロスチェック
有料コンセンサス
IFIS / QUICK 系 等		アナリストコンセンサス、目標株価有料要検討
推奨構成 J-Quants（有料ライト）＋ EDINET（無料） を基盤にし、市場期待（コンセンサス）だけは入手可否・費用を見て段階導入。まず無料枠で骨組みを作り、必要に応じ有料化します。

出典記録（Provenance）— 必須設計

すべての取得データに次のメタデータを付与し、data/metadata/ に保存＋データ本体にも埋め込みます。

# 1回の取得に対するメタデータレコード（例）
source:            "J-Quants /fins/statements"
source_type:       "official_api"
api_version:       "v1"
fetched_at_utc:    "2026-08-09T02:15:00Z"
fetched_at_jst:    "2026-08-09T11:15:00+09:00"
target_entity:     "7203 トヨタ自動車"
accounting_period: "FY2026 Q1 (2025-04-01..2025-06-30)"  # 会計期間
disclosure_date:   "2025-08-01"    # 入手可能になった日（PIT用）
data_hash:         "sha256:..."    # 改変検知・再現性

プログラム・フォルダ構成

実装言語は Python 想定（既存 index.html は保持）

06

銘柄スクリーニング機能

広いユニバースから深掘り候補を絞る ── 足切りであって推奨ではない

条件カテゴリ

バリュエーション（PER/PBR/利回り・過去レンジ下位）／成長性（CAGR・連続増収増益）／財務健全性（自己資本比率・負債/EBITDA・FCF）／収益性（ROE・ROIC>WACC）／株価・需給（相対力・流動性）／市場期待（上方修正・実績>コンセンサス）／除外条件（債務超過・上場浅い 等）。

出力と透明性

条件通過リスト（CSV＋Markdown表）。各銘柄がどの条件を満たし／落ちたかの内訳を明示。総合スコアで参考順位づけ。「割安×成長」「高配当×健全」等のプリセットを設定ファイルに定義。

設計上の要点条件はすべて設定ファイル化（コード変更なしで調整可能）。スクリーニング条件は §09 バックテストと同じルール定義を共有し、条件自体を過去検証できるようにします。
07

決算分析機能

実績・会社計画・市場期待の3軸で「決算の中身」を構造化

  • 実績評価：売上/各利益の前年同期比・QoQ、利益率変化
  • 会社計画比：通期計画への進捗率（季節性補正の注記）、達成確度
  • 修正・サプライズ：上方/下方修正の有無・幅・理由、実績 vs コンセンサス
  • 質の評価：増益の中身（本業か一過性か、為替影響、特益/特損）
  • セグメント：伸びている／縮んでいる事業（EDINET注記を活用）
  • ガイダンス解釈：会社トーン（保守/強気）を過去の達成実績と対比
イベント連携決算発表予定日を監視し、発表後に当該銘柄の決算分析を自動実行 → 監視リスト（§10）へ差分反映。出力は「ポジティブ／ネガティブ／要監視」の3分類で提示します。
08

企業比較機能

複数銘柄を同一基準で横並び比較

比較軸

規模／成長性（CAGR）／収益性（利益率・ROE・ROIC）／財務（自己資本比率・負債・FCF）／バリュエーション（PER/PBR/PSR/EV·EBITDA/利回り）／株価（対TOPIX相対力）／市場期待（目標株価乖離）／総合スコアと11モジュール別サブスコア。

比較の作法

業種・会計基準の違いを明示（例：銀行と製造業のPBRは比較不可）。単純な優劣でなく「どの投資家視点で優位か」を併記。偏差値化・パーセンタイルで相対位置を表現。

出力比較表（CSV＋Markdown）とレーダー／バーチャート（HTMLダッシュボード）。「割安かつ成長」「割高だが質が高い」等の分類コメントを添えます。
09

バックテスト機能

本システムの核心 ── 手法そのものが過去に有効だったかを検証する

スクリーニング条件・スコアリングを過去の任意時点に適用したら、その後どうなったかを測ります。手法の有効性・安定性・弱点を定量化し、人間がルールを改善できるようにします。

検証の枠組み

基準日ごと（月次/四半期）にルール適用 → 上位N銘柄でポートフォリオ構成 → 次リバランスまでのリターンを記録。ベンチマークは TOPIX（配当込み）。

評価指標

累積/年率リターン、超過リターン、勝率、最大ドローダウン、シャープ／ソルティノ。手法妥当性は IC（情報係数）・分位ポートフォリオ（Q1〜Q5）の単調性・ヒットレシオ。

バイアス排除 ── 設計の生命線
  • 先読み（look-ahead）防止：財務は「開示日」を使い、基準日時点で未開示のデータは使わない
  • 生存者バイアス防止：ユニバースに廃止銘柄を含む（上場当時の構成で判定）
  • リスタテメント注意：後日修正値でなく当時発表値（as-reported）を優先
  • 取引コスト・流動性：売買代金下限、手数料・スリッページを控除可能に
  • 過剰最適化防止：学習/検証期間を分ける（walk-forward）。過度なパラメータ調整を戒める注記を出力
10

監視・継続追跡の仕組み

候補・保有・ウォッチ銘柄をフォローし「変化」を検知して通知

監視リスト管理

各銘柄に「追加理由」「追加時点のスコア」に加え、投資仮説とその検証条件・反証条件を紐付け。仮説は「進行中/支持/否定/要見直し」で状態管理。

検知イベント

決算発表 → 自動で決算分析／業績修正の開示／総合スコアの閾値超え変動／バリュエーションのレンジ逸脱／相対力の急変・新高値安値／空売り・信用残の変化。

運用（定期実行）日次/週次バッチ。Claude Code on the web の Trigger / Routine（スケジュール実行）やローカル cron で「取得 → 差分検知 → レポート生成」を回します。出力は監視ダッシュボード（HTML）と変化アラート（Markdown／差分：何が・いつ・どれだけ・出典つき）。
11

レポート出力設計

3形式を目的で使い分け

形式用途特徴
Markdown個別分析・決算サマリー・変化アラートGit差分で履歴追跡でき、レビューしやすい（一次成果物）
HTMLスクリーニング/比較/監視ダッシュボードチャート・インタラクティブ表。閲覧性重視（既存 index.html 資産を活用可）
CSVスクリーニング結果・比較表・バックテスト時系列二次利用・表計算・再分析向け
全レポート共通の必須要素 データ出典一覧（ソース・APIバージョン）／取得日時（UTC·JST）と対象期間／データ充足度・欠損の明示（判定保留を隠さない）／免責（分析材料であり売買推奨ではない）／再現情報（使用したルール設定のバージョン）。個別銘柄レポートは結論の前に必ず「反証（弱気シナリオ）」を載せます。

実現性の整理

現在できること／追加で必要なもの／技術的に難しいこと

✓ 現在できること

アーキ全体の構築／無料データでの骨組み（J-Quants無料枠・EDINET・yfinance）／11分析モジュール／スクリーニング・比較・個別・決算分析／出典記録・対象期間の記録／Markdown・CSV・静的HTML／バックテストの枠組み／Trigger·cronでの定期実行。

＋ 追加で必要

J-Quantsアカウント（履歴拡張は有料推奨）／EDINET登録（無料）／市場期待＝有料コンセンサス契約／Python実行環境と依存ライブラリ／秘密情報管理（.env、キーは非コミット）／10年データの永続ストレージ方針。

△ 技術的に難しい

コンセンサスの入手と時系列スナップ蓄積／PIT財務の厳密性（開示日・リスタテメント分離）／生存者バイアス対策の完全性／短信ガイダンスの構造化／無料ソースのデータ品質クロスチェック／コンテナ揮発性への対応。
